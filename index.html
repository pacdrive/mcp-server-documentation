01. La pregunta

01. The Question

En la ingeniería de automatización industrial, el desarrollo sobre plataformas complejas como PacDrive3 exige un profundo conocimiento de estructuras, plantillas y APIs de scripting. Tras conocer el estándar abierto MCP (Model Context Protocol) en un webinar técnico y corroborar la creciente inquietud de diversos clientes en ferias del sector como Advanced Factories, surgió una pregunta directa: ¿Es posible ir más allá de los asistentes de chat conversacionales y permitir que una IA opere directamente el entorno de ingeniería industrial?

In industrial automation engineering, development on complex platforms such as PacDrive3 requires deep knowledge of structures, templates, and scripting APIs. After learning about the open standard MCP (Model Context Protocol) in a technical webinar and confirming the growing interest of various clients at industry trade shows like Advanced Factories, a direct question arose: Is it possible to go beyond conversational chat assistants and allow an AI to directly operate the industrial engineering environment?

Así que, durante las vacaciones de verano, decidí desarrollar mi propio servidor MCP como experimento práctico con un objetivo claro: evaluar el potencial real de utilizar un modelo de lenguaje a través de Claude Desktop para operar directamente sobre EcoStruxure Machine Expert, ejecutando tareas complejas, repetitivas y propensas a errores dentro del software real de trabajo, sin intermediarios ni simulaciones opacas.

So, during the summer break, I decided to develop my own MCP server as a practical experiment with a clear objective: to evaluate the real potential of using a language model via Claude Desktop to operate directly on EcoStruxure Machine Expert, executing complex, repetitive, and error-prone tasks within the actual work software, without intermediaries or opaque simulations.

02. Elegir dónde ponerlo a prueba

02. Choosing Where to Test It

Para que el experimento tuviera sentido, necesitaba algo más que una demostración sencilla. Elegí PacDrive3 —el sistema de motion control de alto rendimiento de Schneider Electric para la maquinaria más compleja— y una de las plataformas más complejas de programar.

For the experiment to make sense, I needed more than a simple demo. I chose PacDrive3 —Schneider Electric's high-performance motion control system for the most complex machinery— and one of the most challenging platforms to program.

Su Template Full Programming Framework no es un punto de partida vacío: es una estructura completa, preparada para adaptarse a máquinas con combinaciones muy distintas de módulos, ejes y opciones de configuración. Precisamente esa complejidad lo convertía en el campo de pruebas ideal: si la IA podía aportar valor aquí, tendría sentido explorar su uso en tareas reales de ingeniería.

Its Template Full Programming Framework is not an empty starting point: it is a complete structure, prepared to adapt to machines with very different combinations of modules, axes, and configuration options. Precisely that complexity made it the ideal testbed: if AI could add value here, it would make sense to explore its use in real engineering tasks.

03. Cuando la idea se encuentra con la realidad

03. When the Idea Meets Reality

El primer obstáculo no fue MCP, fue la propia integración con la plataforma de ingeniería. Claude podía actuar como cliente MCP desde su aplicación de escritorio, pero la API de Scripting de Machine Expert funciona sobre IronPython 2.7, mientras que el servidor MCP necesitaba ejecutarse sobre una versión moderna de Python (CPython 3.x). Los dos entornos no podían resolverse dentro de un mismo proceso.

The first obstacle was not MCP, but the integration with the engineering platform itself. Claude could act as an MCP client from its desktop app, but Machine Expert's Scripting API runs on IronPython 2.7, whereas the MCP server needed to run on a modern Python version (CPython 3.x). Both environments could not be resolved within a single process.

La solución fue separar la arquitectura en dos partes y construir un puente específico entre ellas:

The solution was to separate the architecture into two parts and build a specific bridge between them:

  • Claude Desktop: Recibe la petición en lenguaje natural y decide qué herramienta utilizar.
  • Servidor MCP (CPython): Expone el catálogo de herramientas y traduce la decisión en una orden concreta (payload JSON).
  • Bridge Interno (IronPython 2.7): Se ejecuta dentro de Machine Expert y llama a su API de Scripting real en el hilo principal de interfaz (GUI thread).
  • Machine Expert: Ejecuta la operación sobre el proyecto abierto, siendo visible en todo momento para el usuario.
  • Claude Desktop: Receives the natural language request and decides which tool to use.
  • MCP Server (CPython): Exposes the tool catalog and translates the decision into a concrete command (JSON payload).
  • Internal Bridge (IronPython 2.7): Runs inside Machine Expert and calls its real Scripting API on the main UI thread (GUI thread).
  • Machine Expert: Executes the operation on the open project, remaining visible to the user at all times.

MCP conecta a Claude únicamente con el servidor MCP. El tramo entre el servidor y Machine Expert es un canal aparte, construido específicamente para este proyecto — no forma parte del protocolo estándar MCP. La arquitectura completa de comunicación queda resumida en el siguiente esquema:

06. Hacer que funcione no era suficiente

06. Making It Work Wasn't Enough

A medida que crecía el catálogo apareció una cuestión crítica: ¿cómo garantizar que las herramientas ejecutan exactamente lo que prometen sin comprometer la integridad del proyecto? Se plantearon dos niveles complementarios de validación:

As the catalog grew, a critical question arose: how to ensure that tools execute exactly what they promise without compromising project integrity? Two complementary levels of validation were established:

  • 662 tests automatizados: Comprueban la coherencia interna del código, garantizando la estabilidad del servidor MCP y permitiendo iterar rápidamente ante cualquier modificación. Estos tests se ejecutan de forma independiente de EcoStruxure Machine Expert, sin necesidad de abrir ni ejecutar el entorno de ingeniería.
  • Validación en vivo contra instalación real: Verifica los comportamientos dinámicos del API de Scripting que las simulaciones offline no pueden detectar.
  • 662 Automated Tests: Check internal code consistency, ensuring MCP server stability and allowing rapid iteration upon any modification. These tests run independently of EcoStruxure Machine Expert, without requiring the engineering environment to be open or running.
  • Live Validation Against Real Installation: Verifies dynamic behaviors of the Scripting API that offline simulations cannot detect.

07. Lo que apareció mientras lo construía

07. What Appeared While Building It

El experimento comenzó buscando automatizar operaciones cotidianas. Durante el desarrollo, también sacó a la luz comportamientos sutiles del software que valía la pena evidenciar:

The experiment started by automating everyday operations. During development, it also brought to light subtle software behaviors worth highlighting:

Caso 1: Convertir un servodrive sin perder su configuración (Lexium LXM62 → LXM52)
Case 1: Converting a Servo Drive Without Losing Configuration (Lexium LXM62 → LXM52)

Tras configurar un Lexium LXM62 surgió la necesidad de sustituirlo por un LXM52. El entorno permite cambiar el tipo mediante "Convert Device". La investigación reveló un detalle importante: si existen módulos hijo incompatibles con el nuevo dispositivo, se eliminan automáticamente durante la conversión sin el aviso explicativo que sí muestra la interfaz gráfica habitual.

After configuring a Lexium LXM62, the need arose to replace it with an LXM52. The environment allows changing the type via "Convert Device". Research revealed an important detail: if incompatible child modules exist with the new device, they are automatically deleted during conversion without the explanatory warning normally shown by the GUI.

✓ Solución MCP: La herramienta compara el estado del dispositivo antes y después del cambio, reportando explícitamente cualquier elemento que se haya eliminado.

✓ MCP Solution: The tool compares the device state before and after the change, explicitly reporting any element that has been removed.

Caso 2: Reordenar módulos de E/S remota sin pérdidas inadvertidas (EdgeIO)
Case 2: Reordering Remote I/O Modules Without Inadvertent Losses (EdgeIO)

Una cabecera EdgeIO exige que su primer módulo sea de alimentación. Al reordenar la isla de módulos, extraer el primer módulo de su posición original provoca su eliminación completa de la estructura sin alerta previa.

An EdgeIO head requires its first module to be a power supply. When reordering the module island, extracting the first module from its original position causes its complete deletion from the structure without prior alert.

✓ Solución MCP: La herramienta verifica la lista completa de elementos antes y después de cada movimiento, haciendo visible cualquier desaparición de módulo.

✓ MCP Solution: The tool checks the complete list of elements before and after each movement, making any module disappearance visible.

08. Dónde está hoy y El experimento continúa

08. Where It Stands Today & The Experiment Continues

La primera versión del servidor tiene un alcance deliberadamente acotado y seguro: opera en modo offline sobre el proyecto abierto, con comunicación 100% local y con un catálogo de herramientas cerrado sin capacidad de ejecutar código arbitrario.

The first version of the server has a deliberately limited and secure scope: it operates in offline mode on the open project, with 100% local communication and a closed tool catalog with no capability to execute arbitrary code.

El roadmap para próximas iteraciones contempla:

The roadmap for future iterations includes:

  • Lenguajes gráficos (FBD, LD): Extender la manipulación lógica más allá de Texto Estructurado (ST).
  • Modo online: Funciones de diagnóstico y lectura directa sobre el hardware real.
  • Herramientas de alto nivel: Manipulación directa del template a nivel de módulos completos de máquina (Template Modules).
  • Graphical Languages (FBD, LD): Extend logic manipulation beyond Structured Text (ST).
  • Online Mode: Diagnostic functions and direct reading on real hardware.
  • High-Level Tools: Direct manipulation of the template at the level of complete machine modules (Template Modules).
